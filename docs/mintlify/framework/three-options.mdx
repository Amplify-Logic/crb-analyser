# The Three Options Model

Every CRB recommendation presents three distinct implementation paths. This isn't arbitrary — it ensures you see the full spectrum of options before deciding.

## Why Three Options?

Most technology decisions default to one extreme: the cheapest SaaS tool or a full custom build. The Three Options Model forces a structured comparison:

1. You see the **real trade-offs** between speed, cost, and fit
2. The NET score makes the **best option mathematically obvious**
3. You avoid **anchoring** on the first solution you find

## The Three Options

### Option A: Off-the-Shelf

The most accessible, general-purpose solution.

| Attribute | Typical Characteristics |
|-----------|----------------------|
| **Cost** | Lowest upfront, subscription-based |
| **Time to deploy** | Days to weeks |
| **Customisation** | Limited to configuration options |
| **Risk** | Lowest technical risk, highest vendor dependency |
| **Best for** | Common problems, tight budgets, quick wins |

### Option B: Best-in-Class

The premium solution with deeper capabilities and better fit.

| Attribute | Typical Characteristics |
|-----------|----------------------|
| **Cost** | Moderate, often includes implementation services |
| **Time to deploy** | Weeks to months |
| **Customisation** | Significant via APIs and integrations |
| **Risk** | Moderate — more complex but better supported |
| **Best for** | Specific needs, growing teams, strategic investments |

### Option C: Custom Build

A purpose-built solution tailored to your exact requirements.

| Attribute | Typical Characteristics |
|-----------|----------------------|
| **Cost** | Highest upfront, lowest long-term per-unit cost |
| **Time to deploy** | Months |
| **Customisation** | Unlimited |
| **Risk** | Highest technical risk, lowest vendor dependency |
| **Best for** | Unique requirements, competitive differentiation, AI-native workflows |

<Note>
  CRB always includes a Custom Build option because AI development costs are dropping 50%+ year-over-year. What was prohibitively expensive last year may now be viable.
</Note>

## Connect vs Replace

For each option, CRB also recommends whether to:

| Strategy | When to Use |
|----------|------------|
| **Connect** | Your existing tool works well enough — integrate the new capability alongside it |
| **Replace** | Your existing tool is the bottleneck — migrate to the new solution |

This prevents unnecessary migrations when a simple integration would deliver 80% of the value.

## How to Read an Options Comparison

Every CRB recommendation includes a comparison table:

| | Off-the-Shelf | Best-in-Class | Custom Build |
|-|---------------|---------------|--------------|
| **Annual Cost** | EUR X | EUR X | EUR X |
| **Implementation** | X weeks | X weeks | X months |
| **NET Score** | X | X | X |
| **Confidence** | High | Medium | Low |
| **Strategy** | Connect | Replace | Replace |
| **Recommendation** | | **Recommended** | |

The recommended option is always the one with the highest NET score, but the report explains why — so you can make an informed decision even if your priorities differ from the score.
